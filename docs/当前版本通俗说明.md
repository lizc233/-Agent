# 袋鼠可信客服 Agent：当前版本通俗说明

## 这个项目现在是什么

它不是一个“把问题发给大模型，再把回答显示出来”的普通聊天窗口，而是一套小型外卖客服处理系统。

用户登录后提出问题，程序会先判断要做什么，再查询当前用户自己的订单、检索客服规则、检查风险和证据，最后才让 DeepSeek 组织客服回复。回答中引用的规则可以点击查看；如果网络或 API 不可用，程序会切换到本地能力继续运行。

## 一次问题是怎样处理的

可以把它理解成一个客服主管带着几名专员协作：

```text
用户提问
  → 规划问题属于什么任务
  → 订单专员查询当前登录用户的 MySQL 订单
  → 规则专员用 bge-m3 检索客服知识库
  → 记忆专员回顾最近对话
  → 风险专员检查越权和高风险内容
  → 证据审核确认订单归属和规则来源
  → 必要时创建或复用售后工单
  → DeepSeek 根据这些材料生成正式回复
```

这些任务中互不依赖的部分会并行执行，因此它不只是顺序调用几个函数。界面中的“Agent 执行详情”可以查看本轮用了哪些 Agent、执行顺序和耗时。

## 为什么它属于 Agent 项目

普通 RAG 的流程通常是“检索文档，然后回答”。这个项目在 RAG 外还增加了任务规划、工具选择、状态管理和行动能力。

例如用户说“刚才的外卖被弄洒了”，Agent 可以判断需要订单信息，主动查询当天订单；如果有多笔订单，就让用户选择；选定后继续原来的问题，而不是要求用户重新描述。证据满足时还可以创建售后工单，这属于对业务工具的实际调用，而不仅是生成文字。

## 记忆现在怎样工作

记忆分成两层。

第一层是当前会话状态，记录当前选中的订单、尚未处理完的问题、系统正在等待用户补充什么，以及用户已经确认的事实。这一层解决“这个订单”“刚才那个问题”等连续对话。

第二层是对话记忆。每轮结束后，系统保存该轮的“用户问题 + 正式客服回复”。下一次调用 DeepSeek 时，会把当前会话最近五轮问答同时交给任务规划模型和回答模型，让模型真正看到前文，而不是只看到一个问题类型标签。

历史问题类型只是参考。如果用户这一轮换了问题，例如上一轮问洒漏、下一轮问异物，系统应当以新问题为准，重新检索整个知识库，而不是被旧标签限制。

## 可信性体现在哪里

可信性不是简单显示一个“可信”图标，而是有实际约束：

- 订单必须由 MySQL 工具查询，并且属于当前登录用户；模型不能自行指定用户 ID。
- 客服结论必须命中带来源的规则文档，界面提供可点击链接供用户核对。
- 本地 bge-m3 负责语义检索，不需要为“偷吃”“吃掉”“拿去填肚子”等每种说法分别建立词条。
- 相似度不足或候选规则难以区分时，系统解释缺少什么依据，而不是强行编造答案。
- 订单状态保留为参考信息，但不会压过用户明确描述的实际售后问题，也不会被 Agent 擅自回写修改。
- 越权查询、高风险投诉和证据不足分别进入拒绝、人工升级或补充信息流程。

## Skills 和 MCP 分别做什么

Skills 可以理解为不同业务场景的操作说明书。目前包含退款、配送事故、食品安全、支付和取消订单等技能，规定某类任务可以调用哪些工具、需要哪些证据，以及什么时候必须转人工。

MCP 可以理解为统一的工具插座。订单查询、规则检索、记忆召回和售后工单能力通过本地 MCP Server 暴露，但用户身份由登录会话提前绑定，模型只能决定调用哪个工具，不能决定冒充哪个用户。

## 售后工单做了什么

对于洒漏、异物、少餐、退款等需要继续处理的问题，证据审核通过后，Case Agent 可以创建或复用售后工单，并记录问题类型、订单、所需材料和处理状态。项目不新增真实外卖订单，也不修改原订单状态；订单数据仍由 MySQL 提供，工单是 Agent 自己的售后处理记录。

## 离线时还能做什么

DeepSeek API 可用时，由模型完成结构化任务规划和正式回复生成。API 不可用时，程序会使用本地规划规则、bge-m3 检索和规则模板进行降级回答，并在执行详情中说明发生了离线降级。

Embedding 模型从本机路径加载，因此语义检索不依赖 Hugging Face 联网下载。MySQL 仍是订单查询与登录功能的必要依赖。

## 桌面端现在具备什么

程序支持登录、注册、桌宠交互、客服聊天、订单选择、历史回答卡片、每条回答独立的执行详情、规则来源链接和系统托盘退出。订单选项点击后会锁定，选中项与未选项使用不同颜色，避免同一操作重复提交。

程序通过 PyInstaller 打包，入口位于：

```text
dist/KangarooCustomerAgent/KangarooCustomerAgent.exe
```

## 当前边界

这是课程设计和个人项目，不是美团真实生产系统。知识库、订单和工单均为模拟数据；规则来源页面用于证明回答依据，不代表真实平台政策。项目没有执行真实退款、真实支付或真实订单创建，也不会把用户描述直接写回订单状态。

目前最适合展示的能力是：可信 RAG、多 Agent 协作、主动工具调用、身份隔离、跨轮任务记忆、售后工单、离线降级和可解释执行链路。
