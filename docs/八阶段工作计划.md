# 美团袋鼠可信客服桌宠 Agent：八阶段工作计划

## 总目标

完成一个 Windows 桌面客服桌宠 Agent：Agent 使用当前用户主键调用 MySQL 查询本人订单状态，再从 JSONL 客服规则中检索回答策略，生成带规则来源链接的回答；证据不足、越权或高风险问题进入拒答、澄清或人工升级流程。DeepSeek 只负责语言理解和生成，不能直接执行 SQL 或绕过业务权限。

## 阶段一：项目基础与环境配置

状态：已完成。

内容：配置读取、MySQL 连接、JSONL 规则加载、健康检查、项目依赖和安全的 `.env` 占位符。

验收：修改本地 `.env` 后，健康检查能报告 MySQL 连接结果和规则加载数量；真实密码不进入代码。

## 阶段二：MySQL Agent 工具

状态：已完成。

内容：实现当前用户订单列表查询和指定订单查询。查询必须同时使用当前用户主键与订单号，只返回订单号和订单状态，并记录必要的 Agent 审计日志。

验收：用户不能查询其他用户订单；Agent 可以主动调用工具获得状态，而不是凭模型记忆回答。

## 阶段三：客服规则检索

状态：已完成。

内容：加载 JSONL 规则，根据问题意图和订单状态匹配退款、配送超时、订单取消等规则，返回客户可读标题、回答策略和来源超链接。

验收：每个有依据的回答都能关联规则编号和来源链接；没有匹配规则时进入知识库不足分支。

## 阶段四：LangGraph Agent 工作流

状态：已完成。

内容：实现问题分类、安全检查、订单查询、规则检索、证据检查、回答、澄清、拒答和转人工节点。

验收：至少跑通“查询订单—检索规则—回答”和“越权—拒绝”两条完整链路。

## 阶段五：DeepSeek 与离线降级

状态：已完成。

内容：接入 DeepSeek 结构化输出；API 不可用时使用本地规则模板回答，仍保留订单查询、来源展示和拒答能力。

验收：无 API 时程序不崩溃、不伪造在线回答，并明确显示离线模式。

## 阶段六：袋鼠桌宠窗口

状态：已完成。

内容：使用 PySide6 实现透明桌面窗口、GIF 播放、悬停手势、可选随机移动、拖拽、系统托盘和客服气泡。

验收：静坐、手势、移动三种素材按约定切换；用户可从任务栏或托盘关闭程序。

## 阶段七：本地运行与联调

状态：已完成。

内容：整合桌宠、Agent、MySQL 和规则来源页面，增加启动检查、异常提示、通知和必要的自动弹窗。

验收：点击启动入口后能完成一次带来源的订单客服对话，并能展示拒答或转人工状态。

## 阶段八：测试、打包与课程材料

状态：已完成。

内容：执行定向测试，记录真实报错到 `报错与解决.md`，使用 PyInstaller 打包 Windows EXE，完善运行说明、实验记录和课程报告材料。

验收：在未打开苍穹外卖的情况下，项目可以独立运行；MySQL 作为唯一外部业务数据依赖，DeepSeek 可选且有离线降级。

## 每阶段的固定检查原则

每次继续开发前先读取本文件，确认当前阶段和验收标准。测试只验证本阶段的目标，不为了增加功能而偏离“当前用户查询 MySQL 订单状态、检索规则并给出可信回答”这条主线。
